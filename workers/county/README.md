# house-recon county Worker

A tiny Cloudflare Worker (free tier) that lets the
[browser analyzer](https://reggie-reuss.github.io/house-recon/) pull the
**county auditor record** — owner, transfer history, value history, current
taxes — the way the CLI does, but with zero install for the user.

Why a Worker here when listing sites needed the extension? County auditor
portals are public government sites with no bot protection — they just don't
send CORS headers, so a web page can't read them directly. The Worker does the
portal's little HTTP dance (session cookie → address search → datalet pages),
strips the HTML to text, and returns JSON with CORS. Results are cached for a
day. A house lookup is ~5 subrequests; the free tier (100k requests/day) is
effectively unlimited for this.

## What the page does with it

When the user picks an address in a supported county (step 1), the page
fetches the record automatically and the report gains:

- **County Record section** — owner, parcel, land use, acres, taxing district,
  current annual tax, effective rate, permits on file
- **Transfers merged into the dated timeline** (sales the listing doesn't show)
- **Ohio tax projection at the asking price** (35% × effective millage −
  rollback credits) vs. the current tax bill
- **Reappraisal red flag** — appraised-value jump ≥15% year-over-year, noted
  as unpermitted-improvement risk when no permits are on file

## Coverage

**31 counties live** — `GET /counties` is the authoritative list (the
analyzer page loads it at startup, so nothing is hard-coded client-side):

- **Ohio** — 5 counties on Tyler **iasWorld** portals (adapter:
  `iasWorldLookup`). Any other iasWorld county is a one-line registry entry.
- **Indiana** — 26 counties on **WTH GIS** (adapter: `wthLookup`).

The registry (`src/counties.js`) is **auto-generated by a discovery crawler**
that walks the NETR public-records directory for whole states, detects each
county's portal platform, and live-verifies a search before inclusion — no
county is hand-picked. Field coverage varies with what each county's portal
publishes; the report prints n/a for the rest.

**Why not every county?** The dominant remaining platform (Schneider
Beacon/qPublic — most of Kentucky, a third of Indiana) returns 403 to any
non-browser client, and many of its Kentucky sites paywall full records, so a
server-side proxy cannot serve them. The realistic path to those is the
companion extension fetching them client-side (a real browser session), plus
an iView-platform adapter for more of Ohio — both roadmap items.

The iasWorld lookup handles both a unique match (the portal redirects
straight to the parcel) and multiple matches (it takes the closest row and
reports the match count so the page can tell the user to double-check).

## Deploy (once, ~3 minutes)

```bash
cd workers/county
npx wrangler login      # opens the browser; free Cloudflare account is fine
npx wrangler deploy     # prints your URL, e.g. https://house-recon-county.<acct>.workers.dev
```

Then paste that URL into `COUNTY_WORKER_DEFAULT` at the top of
[docs/app.js](../../docs/app.js) and push. Until then the feature simply stays
hidden on the page.

## Local development

```bash
npx wrangler dev --port 8799
# then open the analyzer with ?county_worker=http://127.0.0.1:8799
curl "http://127.0.0.1:8799/butler-oh?number=123&street=Main"
```

## Adding a county

- **Another iasWorld county** (many auditors run it — the portal URL looks
  like `…/search/commonsearch.aspx?mode=address`): one entry in `COUNTIES`
  (`src/index.js`) with the host and URL prefix, plus the GEOID→slug row in
  `COUNTY_ROUTES` (docs/app.js). Probe it first — the address form must
  accept `inpNumber`/`inpStreet`.
- **Another platform** (Devnet wEdge, Vision, WTH GIS, …): a new lookup
  function here that returns the same `{ sections }` shape, plus — if its
  page labels differ — parser tweaks in docs/recon.js. The Ohio tax
  projection only applies to `state: "OH"` counties automatically.

## Notes

- Public records only, fetched on a user's explicit request, cached to keep
  load on the county site minimal.
- The portal HTML contains a hidden "System is currently unavailable" banner
  even on good responses — presence of `PARID:` is the success signal, not
  that string.
